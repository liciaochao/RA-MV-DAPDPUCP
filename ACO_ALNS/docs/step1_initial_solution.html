1. 初始解构造的目标与作用

当前工程中“初始解构造”的主入口是 ETPRCBuilder.build_initial_solution()，定义在 src/spd/etprc.py。它在整体算法中的定位不是“最终求优”，而是为后续离线优化提供一个完整、可行、结构化的种子解。

它的作用有四层：

  1. 把全部客户先分配到若干 truck-drone vehicle pair 上，形成全局覆盖的初始方案。
  2. 为每个 pair 构造一条卡车主路径，并从中抽取适合交给无人机执行的 sortie。
  3. 在进入 ACO / ALNS 之前，先给出一个 objective 可计算、约束可检查的基线解。
  4. 为后续优化阶段提供标准解结构：Solution -> VehiclePairSolution -> Sortie。

在整体调用链中的位置如下：

  1. src/spd/main.py::_load_instance() 读取实例，构造 ProblemInstance
  2. src/spd/main.py::_load_parameters() 读取配置，构造 ProblemParameters
  3. ETPRCBuilder.build_initial_solution() 构造初始解
  4. ACOALNSSolver.solve() 或 PureACOOptimizer.solve() 以该初始解为起点继续离线优化

工程上还有一个重要特点：该项目不接受“缺客户”的初始解。build_initial_solution() 末尾如果发现 solution.unserved_customers 非空，会直接抛出 ValueError，不进入后续优化。

3. 构造策略描述

初始解不是单一策略，而是四段式复合启发式：

3.1 客户分组：带配送载重平衡的 K-means 风格聚类

对应函数：ETPRCBuilder._customer_grouping()

核心思路：

  1. 以 instance.vehicle_pair_count 作为簇数 k
  2. 从客户中随机抽取初始质心
  3. 反复执行“分配到最近质心 -> 更新质心”
  4. 若出现空簇，从最大簇迁移一个最远客户过去
  5. 聚类完成后，再按“配送重量不超过卡车容量”做二次平衡

这一步兼顾了两个目标：

  • 几何上把近邻客户放在一个 pair 内
  • 物理上避免某个分组在配送重量上先天过载

3.2 卡车路径构造：带死锁回退的 cheapest feasible insertion

对应函数：ETPRCBuilder._build_truck_route()

它不是简单最近邻，而是“全局扫描所有未插入客户的所有插入位置”，选择代价最小且可行的插入。

插入代价为：

  • 距离增量项
  • 时间窗紧迫度项

实现上使用：

  • omega_distance * delta_dist
  • omega_time_window * (1 / tw_tightness)

如果当前 route 对所有剩余客户都找不到可行插入位，则进入两层回退：

  1. priority inversion：优先尝试时间窗最紧客户
  2. 若仍失败：暂时跳过该客户，等 route 主体完成后做 retry pass

3.3 无人机 sortie 抽取：枚举候选 + objective 增益筛选 + 贪心选择

对应函数：ETPRCBuilder._extract_sorties()

这一步从“全卡车服务的 route”中抽取适合改由无人机服务的客户子集。

核心流程：

  1. 先构造一个 baseline：当前 route 全由卡车服务
  2. 枚举所有可能的 (launch_node, recovery_node) 组合
  3. 枚举 launch 与 recovery 之间可候选的客户子集
  4. 对每个子集，调用 _optimize_sortie_order() 求最优客户访问顺序
  5. 用 check_sortie_structure()、compute_truck_timeline()、compute_truck_load()、check_sortie_feasibility() 过滤不可行候选
  6. 用 compute_objective() 比较“抽取前后”的目标值变化 delta_z
  7. 只保留 delta_z > 0 的正收益候选
  8. 按 delta_z 从大到小贪心选择互不冲突的 sortie

这说明当前实现的 sortie 抽取不是拍脑袋规则，而是受目标函数驱动的启发式筛选。

3.4 概率感知后调整：针对低在家概率客户做局部重排

对应函数：ETPRCBuilder._adjust_by_probability()

构造完整解后，还会执行一步后处理：

  • 若低概率客户是 truck customer，则尝试改变它在 truck route 中的位置
  • 若低概率客户是 drone customer，则尝试改变它在 sortie 中的访问顺序

这里的“低概率”阈值当前写死为：

  • threshold = 0.3

每次替换都必须通过：

  • all_hard_constraints_satisfied()

否则立即回滚。这一步属于“概率感知 + 可行性保护”的轻量局部调整。

4. 逐步骤说明构造流程

步骤 0：实例和参数装配

对应函数：

  • src/spd/main.py::_load_instance
  • src/spd/main.py::_load_parameters

主要工作：

  1. 把 JSON 实例读成 ProblemInstance
  2. 把 JSON 配置读成 ProblemParameters
  3. 为后续构造阶段准备客户集合、距离矩阵、时间参数、容量参数、成本参数

步骤 1：进入 build_initial_solution

对应函数：

  • src/spd/etprc.py::ETPRCBuilder.build_initial_solution

主要工作：

  1. 确定随机源：rng or random.Random(0)
  2. 调用 _customer_grouping() 得到 groups
  3. 构造离线阶段默认 home_status = {cid: True}
  4. 逐组构造 pair 解

步骤 2：客户分组

对应函数：

  • src/spd/etprc.py::ETPRCBuilder._customer_grouping

输入：

  • instance
  • params
  • rng

输出：

  • list[set[int]]

主要逻辑：

  1. 取全部客户编号
  2. 使用 instance.vehicle_pair_count 作为分组数
  3. 随机采样质心
  4. 客户按最近质心分配
  5. 更新质心
  6. 若有空簇，从最大簇挪一个最远客户过去
  7. 若某组配送重量超 truck_capacity，把最远的配送客户移动到最近的可行组

步骤 3：为每个 group 构造卡车主路径

对应函数：

  • src/spd/etprc.py::ETPRCBuilder._build_truck_route

输入：

  • group
  • instance
  • params

输出：

  • 默认返回 list[int]
  • 若 return_skipped=True，返回 (route, skipped_customers)

主要逻辑：

  1. 从 [depot] 开始逐步插入客户
  2. 对每个未插入客户，枚举全部插入位置
  3. 对每个候选位置，调用内部 is_route_feasible() 检查：

    4. - 客户时间窗是否被破坏
    - truck load 是否超容量
    - 最终回仓时间是否超 depot_latest

  4. 选择最小代价可行插入
  5. 若所有客户都不可插入，改按“时间窗最紧”顺序尝试
  6. 若仍不可插入，则先跳过最紧客户
  7. 最后对跳过客户做 retry pass
  8. route 末尾补上 depot

步骤 4：从全卡车路径中抽取 sortie

对应函数：

  • src/spd/etprc.py::ETPRCBuilder._extract_sorties

输入：

  • truck_route
  • instance
  • params
  • home_status

输出：

  • updated_route
  • sorties
  • truck_customers
  • drone_customers

主要逻辑：

  1. 构造 baseline pair：不抽 sortie，所有客户都由 truck 服务
  2. 计算 baseline objective
  3. 枚举 launch / recovery 节点对
  4. 枚举中间可由无人机服务的客户子集
  5. 对客户子集调用 _optimize_sortie_order() 求最优顺序
  6. 构造 candidate pair
  7. 调用：

    8. - check_sortie_structure
    - compute_truck_timeline
    - compute_truck_load
    - check_sortie_feasibility
    - compute_objective

  8. 计算 delta_z = baseline_objective - candidate_objective
  9. 对正收益候选按 delta_z 降序排序
  10. 贪心选择不冲突的 sortie，并从 route 中删除对应 drone customers

步骤 5：优化 sortie 内部客户顺序

对应函数：

  • src/spd/etprc.py::ETPRCBuilder._optimize_sortie_order

输入：

  • customers
  • launch
  • recovery
  • instance
  • params
  • home_status

输出：

  • 排序后的 list[int]

主要逻辑：

  1. 若客户数 <= 1，直接返回
  2. 枚举 customers 的全部排列
  3. 对每个排列构造一个简化 pair
  4. 调用结构检查、timeline/load 计算、sortie feasibility 检查
  5. 用 compute_objective() 选 objective 最小的顺序
  6. 若所有排列都不可行，则返回原始顺序

步骤 6：处理 route 构造时被跳过的客户

该逻辑在 build_initial_solution() 内部，不是单独函数。

主要逻辑：

  1. 汇总所有 pair 在 _build_truck_route(..., return_skipped=True) 中跳过的客户
  2. 按时间窗宽度从宽到窄尝试“跨 pair 插入”
  3. 在各 pair 现有 truck_route 的各位置尝试插入
  4. 插入后必须同时满足：

    5. - route 时间推进仍可行
    - 回仓仍可行
    - 原 sorties 的 launch / recovery 节点仍存在于新 route
    - 原 sorties 的 launch / recovery 顺序没有被破坏

  5. 插入成功则记为 rescued
  6. 若最终仍有未插入客户，保留在 unserved_customers

步骤 7：概率感知后调整

对应函数：

  • src/spd/etprc.py::ETPRCBuilder._adjust_by_probability

主要逻辑：

  1. 拷贝当前 solution，避免失败修改污染原始对象
  2. 对每个 pair 计算 truck timeline
  3. 计算每个客户在当前 arrival time 下对应的 home probability
  4. 按概率升序处理客户
  5. 若 prob < 0.3：

    6. - truck customer：尝试重新插入到 route 的其他位置
    - drone customer：尝试重排其所在 sortie 的客户顺序

  6. 任何候选替换都必须通过 all_hard_constraints_satisfied() 才接受
  7. 最后重算 unserved_customers

步骤 8：最终完整性检查

仍在 build_initial_solution() 内部。

主要逻辑：

  1. 汇总所有 pair 已分配客户
  2. 计算 unserved = all_customers - assigned_customers + skipped_in_route_build
  3. 若 solution.unserved_customers 非空，直接抛出异常
  4. 返回完整初始解

5. 伪代码

FUNCTION BuildInitialSolution(instance, params, rng):
    random_state <- rng if rng != None else Random(0)
    groups <- CustomerGrouping(instance, params, random_state)
    home_status <- {cid: True for cid in instance.customers}

    vehicle_pairs <- []
    skipped_global <- {}

    FOR each group g with index p:
        route, skipped <- BuildTruckRoute(g, instance, params, return_skipped=True)
        skipped_global <- skipped_global U skipped

        updated_route, sorties, truck_set, drone_set <-
            ExtractSorties(route, instance, params, home_status)

        vehicle_pairs.append(
            VehiclePairSolution(
                pair_id = p + 1,
                truck_route = updated_route,
                sorties = sorties,
                truck_customers = truck_set,
                drone_customers = drone_set
            )
        )

    IF skipped_global is not empty:
        skipped_global <- RescueSkippedCustomersAcrossPairs(
            skipped_global, vehicle_pairs, instance, params
        )

    solution <- Solution(
        vehicle_pairs = vehicle_pairs,
        unserved_customers = AllCustomers(instance) - AssignedCustomers(vehicle_pairs)
                             U skipped_global
    )

    solution <- AdjustByProbability(solution, instance, params)

    IF solution.unserved_customers is not empty:
        RAISE ValueError("ETPRC failed to serve all customers")

    RETURN solution


FUNCTION BuildTruckRoute(group, instance, params):
    route <- [depot]
    uninserted <- group
    skipped <- []

    WHILE uninserted not empty:
        try cheapest feasible insertion over all customers and positions
        IF found:
            apply best insertion
            CONTINUE

        try priority inversion:
            attempt tightest time-window customer first
        IF found:
            apply insertion
            CONTINUE

        skip the tightest-window customer temporarily

    retry skipped customers on the completed route
    append depot
    RETURN route, skipped


FUNCTION ExtractSorties(route, instance, params, home_status):
    baseline_objective <- objective(all-truck route)
    candidate_pool <- []

    FOR each launch node in route:
        FOR each recovery node after launch:
            enumerate feasible customer subsets between them
            optimize customer order for each subset
            check structure, timeline, load and sortie feasibility
            compute delta objective
            keep only positive-gain candidates

    sort candidate_pool by delta descending
    greedily pick non-conflicting sorties
    remove selected drone customers from truck route
    RETURN updated_route, selected_sorties, truck_customers, drone_customers

10. 发现的不确定点或需用户确认的内容

10.1 etprc.k_cluster 与 instance.vehicle_pair_count 的关系

虽然配置对象 ETPRCParameters 中存在 k_cluster，实验脚本 run_experiments.py 也会根据实例把它写入配置，但 _customer_grouping() 当前实际使用的是：

  • k = instance.vehicle_pair_count

也就是说，当前初始解分组数是由实例决定，不是由 params.etprc.k_cluster 决定。需要确认这是否为有意设计。

10.2 omega_balance 当前未被消费

ETPRCParameters 中定义了：

  • omega_balance

但在 src/spd/etprc.py 当前实现里，初始解构造阶段没有看到该参数被直接用于分组、插入或 sortie 抽取。需要确认：

  1. 它是否只是历史遗留参数
  2. 或者原计划用于分组平衡但尚未实现

10.3 概率调整阈值是硬编码

_adjust_by_probability() 中的低概率判定阈值当前写死为：

  • threshold = 0.3

它不在配置文件中，属于代码级硬编码。若后续分析要讨论“关键参数”，需要把它归类为实现常量而不是配置参数。

11. 初始解构造策略概括（2~3句话）

当前实现以 E-TPRC 为主入口：先按车辆对数量做随机初始化的 K-means 分组，再对每个分组执行带时间窗和载重约束的 cheapest-feasible-insertion 卡车路径构造。然后从全卡车路径中枚举并筛选正收益 sortie，用 objective 差值而不是单一距离规则做贪心抽取，最后再对低在家概率客户做一次可回滚的概率感知调整。
